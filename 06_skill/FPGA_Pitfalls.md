# FPGA 项目实施踩坑与排查指南 (VLC 项目实录)

## 坑 1：多驱动报错 (Multiple Driver Nets)
- **触发条件**：在代码中同一个 reg 变量在不同的 always 块中被赋值，或在顶层被 assign 和例化同时驱动。
- **排查步骤**：定位报错行，确保每个变量只在唯一的一个 always 块中赋值；内部 reg 通过 assign 赋给 wire 输出引脚。
- **总结来源**：VLC 系统中接收模块由于复位信号和状态机信号冲突，导致报错。必须严格分离“内部寄存器”和“物理引脚”。

## 坑 2：综合能过，但生成 MCS 固化文件失败 (SPI_BUSWIDTH)
- **触发条件**：Vivado 生成 MCS 时，默认按 1-bit SPI 模式，而实际板卡 Flash 为 4-bit QSPI。
- **排查步骤**：在 Tcl Console 执行 `set_property BITSTREAM.CONFIG.SPI_BUSWIDTH 4 [current_design]`，重新生成 bit，再生成 mcs。
- **总结来源**：烧录固化程序时出现报错，查明是总线宽度不匹配导致。建议将此命令直接写入 XDC 约束文件中。

## 坑 3：仿真波形全为高阻态 (Z) 或 0
- **触发条件**：直接运行仿真，没有编写 Testbench，或者没有把 Testbench 设为顶层。
- **排查步骤**：确认 `Simulation Sources` 中 `tb_xxx.v` 被 `Set as Top`；确保 TB 中提供了时钟翻转（`forever #5 clk = ~clk;`）和复位激励。
- **总结来源**：初做仿真时，没设顶层，Vivado 拿设计文件当顶层，没人给时钟，电路死机。

## 坑 4：光通信 PWM 接收端状态机卡死 (死锁)
- **触发条件**：PWM (脉宽调制) 解调宽度阈值设置太窄，或接收状态机没有错误复位机制。
- **排查步骤**：放大判定阈值 (如从 10~18 放宽到 5~22)；在状态机中加入防错逻辑，若 `rx_bit_error == 1` 则立刻把状态机重置回 IDLE，重新寻找 `A6` 帧头。
- **总结来源**：通信时拔线导致波形畸变，接收端状态机错一位后永远卡死。

## 坑 5：单板自环测试没信号 (K14 连 H14)
- **触发条件**：单板回环，但是代码里根本没有写 K14 的发送逻辑，或者 K14 没在 XDC 里约束。
- **排查步骤**：检查代码顶层是否包含 `output VLC_TX_PIN`；检查 XDC 中是否写了 `set_property -dict {PACKAGE_PIN K14 ...} [get_ports VLC_TX_PIN]`。
- **总结来源**：RX 端没有内部发射机，用一根线短接也是瞎短接。

## 坑 6：长时间运行导致 FIFO 溢出丢包
- **触发条件**：发送端光通信帧间隔太短，略微快于接收端串口（如 9600bps）的发送速率，长时间跑导致接收 FIFO 累积直至写满。
- **排查步骤**：调整 `vlc_tx_ctrl` 里的 `timewait` 等待参数，使物理层组帧的吞吐率严格匹配或略微低于串口波特率的吞吐率。同时在 FIFO 写入侧加上 `!full` 保护。
